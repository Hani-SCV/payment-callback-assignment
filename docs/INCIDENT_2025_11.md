# 장애 리포트: 결제 이중 정산 (2025-11)

> 이 문서의 수치와 식별자는 과제를 위한 합성 값입니다.

## 요약

결제 완료 콜백이 중복 수신되면서 정산 데이터가 중복 생성되었습니다. 4건의 주문에서
이중 정산이 발생했고, 수동으로 정정했습니다.

## 경위

1. 공급자 측 타임아웃으로 동일한 완료 콜백이 재전송되었습니다.
2. 레거시 구현은 중복 콜백을 구분하지 않고 성공 응답을 반환했습니다.
3. 재전송된 콜백 중 일부는 **거래 ID가 다른** 별개의 승인 건이었습니다. 조용히
   성공으로 처리되면서 잘못된 거래 ID가 기존 결제 레코드를 덮어썼습니다.
4. 결과적으로 어떤 승인이 실제 결제인지 판별할 수 없는 레코드가 남았습니다.

## 원인 분석

- 재전송(같은 거래)과 별개 승인(다른 거래)을 구분하지 않았습니다.
- 완료 처리와 이벤트 기록이 하나의 트랜잭션으로 묶여 있지 않았습니다.
- 한 주문에 연결된 서로 다른 결제 시도가 동시에 완료 처리될 수 있었습니다.

## 재발 방지 요구사항

1. **재전송과 별개 승인은 반드시 구분해야 합니다.** 같은 거래의 재전송은 조용히
   처리하되, 이미 완료된 결제에 다른 거래 정보가 들어오면 운영팀이 인지할 수 있어야
   합니다. 이 경우를 성공으로 응답하면 안 됩니다.
2. 하나의 외부 거래 ID는 하나의 결제에만 연결되어야 합니다.
3. 한 주문에는 완료된 결제가 하나만 존재해야 합니다. 동시 요청에서도 보장되어야
   합니다.
4. 완료 처리는 전부 반영되거나 전부 반영되지 않아야 합니다.

## 미해결

- 금액 비교에 부동소수점을 사용하는 코드가 남아 있습니다. Alipay 소수점 금액에서
  간헐적 불일치가 보고되었으나 재현하지 못했습니다.
- 콜백 원문을 이벤트 테이블에 그대로 적재하고 있습니다. 보안팀에서 개선 요청이
  등록되어 있습니다.
