# 결제 콜백 마이그레이션 요구사항 메모

작성: 결제 프로덕트팀
대상: 백엔드 마이그레이션 담당자

레거시 PHP에서 Python으로 옮기면서 정리한 요구사항입니다. 기술 구현 방식은
백엔드에서 판단해 주세요.

## 1. 중복 콜백

공급자는 네트워크 상황에 따라 같은 콜백을 여러 번 보냅니다. 브라우저 새로고침으로
return URL이 두 번 호출되는 경우도 흔합니다.

**중복 콜백은 200 OK로 조용히 처리해 주세요.** 공급자 대시보드의 실패율 지표가
올라가면 정산 담당자가 매번 확인 요청을 보내고, 그 대응 비용이 큽니다. 레거시에서도
중복은 그냥 성공으로 응답했습니다.

## 2. 응답 지연

결제 완료 화면 전환이 콜백 응답을 기다립니다. 응답이 느리면 고객이 결제창을 닫고
문의를 남깁니다. 완료 처리는 가능한 한 빠르게 끝나야 합니다.

## 3. 부분 결제

한 주문에 여러 결제 시도가 붙는 경우가 있습니다. 고객이 Toss로 시도했다가 실패한
뒤 Stripe로 다시 시도하는 흐름이 대표적입니다. 주문이 결제 완료되면 나머지 시도는
정리되어야 합니다.

금액이 서로 다른 결제 시도가 한 주문에 남아 있는 경우도 확인되었습니다. 이 경우
처리 방식은 백엔드에서 판단해 주세요.

## 4. 정산 데이터

정산팀은 결제 완료 시점의 금액과 통화를 그대로 필요로 합니다. 반올림이나 통화
환산으로 값이 바뀌면 대사가 깨집니다.

## 5. 알림

결제 완료 알림은 별도 시스템이 발송합니다. 이번 마이그레이션에서는 발송 대상을
기록하는 것까지만 하면 됩니다.
